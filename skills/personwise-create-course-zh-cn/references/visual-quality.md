# 幻灯片与主讲人视觉核验

## 核验前提

只有 `image review-sheet` 成功且当前 Agent 真能理解下载的图片，才能声称完成视觉审阅。
结构化“不支持”响应只停止视觉审阅；命令成功、文件名、尺寸或生成完成不等于视觉通过。
记录 `completed`、`partial` 或 `not_performed`；没有视觉能力本身不阻塞发布。

## 全量审阅

在图片规范就绪后，每批最多六页、使用新的有界目标路径运行：

```text
personwise --account <alias> image review-sheet --project-id <project-id> \
  --slides <页码集合> --dest <新路径> --json
```

需要细节时在本地放大或裁切。必须覆盖全部页面，不能抽样。逐页检查：

- 标题、要点、页内文字、讲稿和来源是否一致；
- 可见文字是否正确、清楚，没有乱码、裁切、重叠或不可读表格；
- 视觉是否真正解释教学任务，而不是装饰；
- 图表、流程、关系和数量是否与内容一致；
- 没有编造数字、品牌、人物身份、UI、设备读数、因果或伪造来源；
- 层级、留白、对比、阅读顺序和移动端缩放是否清楚；
- 整课体系一致，但构图不机械重复；
- 用户批准的参考图影响符合预期。

图标也是主张：对勾暗示成功、锁暗示安全、上升图暗示增长、仪表盘暗示真实 UI/数据、档案
风格暗示真实文物。没有证据就拒绝这些含义。

## 修正与重生成

1. 先读新 `course snapshot`。
2. 内容有错时先用 revision 绑定的 `course update` 做最小一致修正。
3. 读取新 revision。
4. 把完整失败页集合与具体逐页指令放进一次 `image regenerate`。
5. 用有界 `run wait`/`run get` 等到每个目标规范完成。
6. 下载新的变更页审阅表并复检。

不得把失败集合拆成碰运气调用，也不得根据想象重生成。响应不确定时先读权威状态。

## 主讲人核验

先用 `presenter list` 确认语言/声音准备。Agent 能看图时，对认真候选运行
`presenter preview --presenter-id <id> --dest <新路径> --json`，只评价可观察的正式度、亲和/
权威感、能量、表情、服装、取景和教学匹配；不得推断身份、国籍、职业、性格或经历。

选择完整兼容的形象/声音组合。不能看图时只按结构化语言、声音和 profile 状态选择默认组合，
记录 `visual_review_status=not_performed`，不得虚构外观评价。
