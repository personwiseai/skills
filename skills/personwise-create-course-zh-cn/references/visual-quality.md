# 幻灯片与主讲人视觉核验

## 核验前提

只有当前 Agent 真能理解 MCP 返回的图片内容，才能声称完成视觉审阅。工具调用成功、图片状态完成或
拿到资源链接，都不等于视觉通过。

用 `get_slide_review_sheet` 按顺序每批最多六页查看整组；需要细查单页时再用
`get_slide_preview`。同时读取最新 snapshot 的标题、关键点、页面文字和讲稿，不能脱离教学任务只看
美观。

## 每页检查

对每页记录 pass/fail 和具体原因：

- 所有可见文字是否清楚、正确、没有乱码、裁切、重叠或伪造界面；
- 视觉是否真正表达本页教学任务，而非泛化装饰；
- 图表、流程、关系和数量是否与内容一致；
- 视觉没有加入未经支持的数字、品牌、人物身份、设备读数或因果；
- 主次层级、留白、对比和阅读顺序是否清楚；
- 整课保持统一系统，同时页面构图不机械重复；
- 参考图影响符合用户意图，固定图主体没有被重画；
- 主讲人区域不会遮挡关键内容，移动端缩放后仍可理解。

## 整课检查

整组至少检查：

- 开场是否建立主题和期待；
- 中段是否有足够的图形变化支撑概念、步骤和比较；
- 结尾是否形成总结或行动，而非突然停止；
- 色彩、字体感、边距和图形语言是否统一；
- 没有连续多页使用同一构图或无意义库存图；
- 每个用户指定的视觉要求都能对应到具体页面证据。

## 修正顺序

1. 若根因是标题、关键点、页面文字或讲稿错误，先用 `update_slides` 修内容。
2. 重新读取 `get_run` 和 authoring snapshot，取得新 revision。
3. 一次收集完整失败页集合，再调用 `regenerate_slide_images`。
4. 每个失败页写明观察到的缺陷和必须遵守的视觉边界，避免只说“更好看”。
5. 等待规范完成状态，再复查所有变更页及其与相邻页的关系。

不要盲目重画，也不要用替换图隐藏错误课程内容。响应不明确时先读状态，避免重复消耗。

## 主讲人核验

先用 `list_presenters` 确认目标语言声音准备完成。对认真候选调用 `get_presenter_preview`，只评价可观察
的正式度、亲和感、能量、表情、服装、取景和与教学场景的匹配；再核对精确声音映射。

选择完整的形象与声音组合，而不是把一张图片配给不兼容声音。没有视觉能力时，只能依据结构化的
语言、声音就绪和 profile 状态选择，并明确未核验外观。

## 无视觉能力路径

无视觉能力时：

- 要求每页规范图片状态完成；
- 不声称文字、构图、语义、多样性或参考图效果通过；
- 不根据想象调用重生或上传“已审阅”替换图；
- 主讲人只按结构化兼容性选择；
- 记录 `visual_review_status=not_performed` 和真实原因；
- 继续用户已授权的配置与发布流程。
