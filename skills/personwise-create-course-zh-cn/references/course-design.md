# 课程设计准则

## 先定义可验证的教学蓝图

创建前写清以下内容：

- 目标学习者已有知识、使用场景和最终能完成的动作；
- 一句可检验的学习结果；
- 事实权威：主题约束、用户文本、指定资料或允许补充的常识；
- 合理页数与每页唯一教学任务；
- 页面文字、口头讲解、互动问答和评估各自承担什么；
- 视觉系统、主讲人与声音方向、必须避免的误导表达；
- 最终目标 `draft`、`private` 或 `link`。

页数由教学任务决定，不要为了显得完整而填充空页。简短说明可采用“问题—原理—步骤—示例—检查”，
概念课可采用“心智模型—构成—关系—应用—误区”，操作课可采用“目标—准备—步骤—判断—练习”。
只有确实符合主题时才使用这些结构。

## 划定事实边界

`materials_only` 表示课程事实只能来自保留资料。所有关键结论都必须能追溯到资料；资料缺失时停止或
明确降级选择，不得暗中用模型知识补洞。

`open` 允许模型知识，但用户资料中的产品事实、数字、名称、流程和限制仍优先。遇到冲突时保守处理，
不编造客户、指标、价格、资质、功能、政策或来源。

把事实约束写成紧凑、持久的课程 constitution：范围、受众、必须覆盖、不得声称、术语和语气。不要
把临时聊天上下文当作服务器可见事实。

## 设计逐页教学弧线

每页蓝图至少包含：

```text
教学任务
学习者在本页后能说出或做到什么
关键点（通常 2–4 个）
页面上应出现的证据或结构
讲稿需要补充的解释与过渡
视觉任务和禁止出现的元素
```

相邻页面必须有因果、层级或步骤关系。避免连续多页重复定义、同样构图、标题只是换同义词，或把所有
细节塞进一页。

## 分离页面文字与讲稿

页面文字适合扫描：短标题、少量高信息密度要点、必要标签和证据。讲稿负责解释原因、举例、连接前后
页面并指出误区。不要让讲稿逐字朗读页面，也不要在讲稿中加入页面没有事实支撑的新主张。

审阅对齐关系：

```text
标题/关键点决定本页教学边界
页面文字把边界视觉化
讲稿解释边界而不越界
图片帮助理解，不承担唯一事实来源
```

## 设计视觉系统

先确定整课统一的版式节奏、颜色、图形语言和图片角色，再为每页指定视觉任务。优先选择能帮助比较、
顺序、结构、因果或空间关系的图形；装饰性图片不能替代教学信息。

参考图用于主题、构图、色彩或视觉语法；固定图表示用户要求保留原图主体。不要把固定图指令偷偷改成
重画，也不要用视觉吸引力掩盖内容错误。

## 设计主讲人与评估

主讲人选择以目标语言声音可用、形象与教学场景相称、讲述风格一致为准。外观元数据只能作为可观察的
选角信息，不能推断国籍、民族、职业、人格或经历。

评估题只测课程真正教过的目标。错误选项应反映常见误解，不得依赖未出现的冷知识。课程未要求评估
时，不要擅自增加管理流程。
